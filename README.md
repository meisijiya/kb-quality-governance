# 企业知识库质量治理系统（本科毕业设计）

> **题目定稿**：《基于语义聚类与时效性分析的企业知识库质量治理系统设计与实现》
> 仓库性质：2027 届本科毕业设计。选题决策链 + 已完成全链路实测的算法原型（PoC）。
> 排期：17 周，2026-10-14 → 2027-02-09。开发与论文并行，W10 末系统冻结。

---

## 这个仓库解决什么问题

企业把多年积累的制度、操作手册、FAQ 沉淀进知识库后，会积累三类质量缺陷：

| 缺陷 | 定义 | 实测检出效果 |
|---|---|---|
| **知识缺口** | 员工问的问题，知识库里根本没有对应条目 | P 0.80 / R 0.80 / F1 **0.80**（阈值 0.62） |
| **内容腐化** | 文档还在，但内容已过期，反而会被检索命中给出错误答案 | P 0.8986 / R 1.00 / F1 **0.9466**（埋 62 篇，检出 69 篇，FP 7，FN 0） |
| **重复冗余** | 同一件事被不同部门以不同措辞反复写成多篇 | 阈值 0.90 组级 F1 **0.7037**；阈值 0.95 组级 F1 **1.0** |

三模块构成一条完整治理链路：语义聚类把无标签工单归并成业务意图 → 段落级语义覆盖度判定哪些意图没有文档支撑 → 时效性规则识别过期文档 → 余弦相似度识别重复组 → 合并为一份可执行的治理清单。

**与 RAG 的边界**：本课题**不回答问题，只治理知识库本身的质量**。全链路无生成模型，评测对 ground truth 算 P/R/F1。这是本选题的查重护城河，也是答辩必守的边界。

## 核心结论（全部可溯源）

所有数字取自 `poc/kbgovernance/metrics.json` 及其同目录 CSV，改一处口径就全部重算。

### 算法改进点：检索粒度从整篇下沉到段落

同一嵌入模型、同一 `max-cosine` 打分下：

| 粒度 | 意图级 AUC | 工单级 AUC |
|---|---|---|
| 整篇级 | 0.8880 | 0.8307 |
| **段落级** | **0.968** | **0.8659** |

来源：`poc/kbgovernance/granularity.csv`（2 粒度 × 5 打分共 10 行）。

反向点必须一并呈现：整篇级换 `max-min` 时意图级反而到 0.928，高于同粒度 `max-cosine` 的 0.8880。所以本文主张收敛为「**在选定的 `max-cosine` 打分下沉粒度有效，提升幅度有限（+0.080 / +0.035）**」，不写「大幅提升」。

### 负结果：阈值可迁移性不成立

绝对阈值锚定的是「模型 × 语言」的刻度。同模型同语言内跨场景阈值极差仅 0.0264，但刻度稳 ≠ 迁移后效果一样：banking77 全量 → KB 减半时，知识库小了一半、ground truth 从 15 个缺口意图变成 46 个，沿用全量阈值的 S1 / S2 精确率仍是 1.0000、召回掉到 0.4130，F1 从目标场景自身的 0.9474 掉到 0.5846。跨语料则全线崩溃：中文语料标定的 `cover ≤ 0.6463` 搬到英文语料，**正向判定一个缺口都检不出（F1 = 0，该场景自身最优 F1 为 0.8148）**，反向判定则 77 个意图全被误报为缺口（F1 0.3261）——两个方向都不可用。因此题目**不承诺**「阈值可迁移性评测」——那需要一整章篇幅去划定失效边界，会挤掉系统实现本身。

来源：`poc/kbgovernance/standardize/` 下 `results_auc.csv`、`results_xfer_banking77_en.csv`、`results_directions.csv`。

### 腐化判定必须多规则联合

四条规则联合 F1 = 0.9466，去掉任意一条塌到 0.6809–0.6857；`drop_R3` 的 `delta_f1 = 0`（R3 与其余规则语义冗余，如实报告为负面发现）；`only_R2 / only_R3 / only_R4` 单独使用 F1 全为 0.0。

来源：`poc/kbgovernance/corrupt_rule_ablation.csv`（9 行）。

### 运行环境与耗时

纯 CPU，`BAAI/bge-small-zh-v1.5`（512 维，FlagEmbedding，未降级）。向量化 15.43 秒，三模块检测合计 2.85 秒。**耗时字段跨机器必然波动，指标值不受影响。**

## 复现

```bash
cd poc/kbgovernance
"C:/Program Files/Git/bin/bash.exe" run_all.sh
```

`HF_HOME` 必须指向 `D:/hf_cache`（`run_all.sh` 已内置默认值），否则模型权重会落进 C 盘用户目录。预期端到端约 65 秒。

依赖见 `poc/kbgovernance/requirements.txt`。模型加载有三级自动降级（FlagEmbedding → sentence-transformers → TF-IDF char 2-gram），实际用了哪一级写在 `embeddings_meta.json`，`detect.py` 读该文件，保证不会出现「降级了却声称用了 BGE」。

**数字纪律**：`python check_numbers.py` 是门禁脚本，扫三份文档里的每个数值断言，判定它能否在产物里找到出处；找不到出处的格子一律写 `【无出处】`，不允许补一个看起来合理的数。

| `product` | 健康度评分产品、知识库系统、数据治理平台（含 freshness 质量维度） | 答辩商业对标与系统形态定位 |

| `annotate` | 标注协作平台（含标注一致性工作流） | W3 的 300 条人工标注关卡 |

清单、筛选理由、许可证与固定 commit SHA 见 [`reference/REFERENCES.md`](./reference/REFERENCES.md)。需要时按类别重建：

```bash
bash reference/clone_references.sh algo        # 或 product / stack / annotate，或不带参数取全部
```
