# Web 端原型（讨论稿）

> **状态：讨论稿，不是定稿，也不构成契约。**
> 本目录是按 `docs/技术方案/Web端原型设计规格.md` 生成的静态原型，用于在开工前把产品形态、UI 形态、交互细节和视觉基调摆到桌面上讨论。
> 其中依赖的前后端形态、数据形态与视觉方案尚未拍板，见 `docs/技术方案/开发前准备清单.md` §4.11 的 P1–P7。

## 怎么看

直接用浏览器打开 `index.html` 即可，不需要起服务、不需要装任何依赖（纯静态、无外部 CDN、无网络请求）。

三个功能面对应三个页面，左侧导航切换：

| 页面 | 内容 |
|---|---|
| 上传文档与工单 | 语料现状、拖拽导入、导入记录、文档列头对照表、工单导入列头对照表 |
| 一键运行治理扫描 | 扫描前检查、扫描操作、三模块判定指标总览、分项耗时 |
| 三类缺陷清单 | 知识缺口 / 内容腐化 / 重复冗余三个 Tab；判定指标 + 统计单元口径 + 明细列表（行内就地展开）+ 下载 CSV + 口径与免责 |

顶部右侧「状态演示」可以切换成功态 / 未扫描 / 加载态 / 错误态 / 扫描中，用来核对各状态下的文案与空态。

## 数据从哪来

`data.js` 里的每个数字都取自 `poc/kbgovernance/` 的机读产物，与页面上的文案一一对应（见规格书附录 A 的数字溯源表）。原型页面不发起任何真实请求，界面上的接口路径、数据来源、统计单元口径都是**设计标注**，用来核对将来实现时应当对齐的契约。

页面上出现的三个边界是刻意保留的诚实标注，不是没做完：

- 重复冗余 F1 = 1.0000 是**乐观值**，页面底部已标注，论文附录 D 同样标注；
- 聚类耗时与缺口阶段耗时在产物里没有对应字段，页面写「—」并说明原因；
- 全链路总耗时在 `metrics.json` 里没有字段，页面只列分项，不给合计。

## 校验

两个脚本都只读、不改产物，退出码非 0 即视为不通过：

```bash
# 1) 数字纪律：data.js 的每个取值都能在产物里逐条对上，且未透出评测依据列
python system/prototype/check_prototype.py

# 2) 渲染：三个页面 + 三个清单 Tab 实际渲染，无控制台错误、无横向溢出、无 NaN/undefined
python system/prototype/render_check.py
```

`check_prototype.py` 也是防止原型数字随产物复跑而漂移的哨兵：产物一重跑，它就会因对不上而失败，届时按 `poc/kbgovernance/sync_timings.py` 的同一思路重新生成 `data.js`。

`render_check.py` 会在 `shots/` 下留下五个状态的整页截图（上传页 / 扫描页 / 缺口 Tab / 腐化 Tab / 重复 Tab）。

## 目录

```
system/prototype/
├── index.html      # 三页结构与全部页面文案
├── styles.css      # 视觉基调（当前实现为方案 A｜学术清朗：白底 + 单一主蓝强调色）
├── app.js          # 状态切换、Tab 切换、行内展开、数据渲染
├── data.js         # 来自 poc/kbgovernance/ 产物的样例数据
├── check_prototype.py  # 数字溯源校验
├── render_check.py     # 渲染校验 + 截图
└── shots/              # 渲染截图（校验副产物）
```
