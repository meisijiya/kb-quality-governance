## Q1「你为什么不做跨模型 / 跨语言的阈值迁移？试过吗？」

### 问题原话
「阈值可迁移性你没考虑吧？换个模型、换个语种，你的阈值还能用吗？」

### 一句话回答
试过，而且做成了正反两面：**同模型同语言内阈值刻度很稳（跨 5 个场景所需阈值极差只有 0.0264），跨模型或跨语言则全线崩溃**——中文语料上标定的 `cover ≤ 0.6463` 搬到 banking77，**正向判定一个缺口都检不出（0 / 77，F1 = 0）**，反向判定则 77 个意图全被判为缺口（P 0.1948 / R 1.0 / F1 0.3261，该场景自身最优 F1 是 0.8148）。所以失效边界不是「语料」，是「模型 × 语言」这一对。

### 支撑数据
| 数据 | 出处 |
|---|---|
| 中文合成语料 alpha 上 ABS 的最优阈值 cover ≤ **0.6463**（原值 −0.6463） | `standardize/ablation.csv` 第 2 行「最优阈值」列 |
| 该阈值搬到 banking77：**反向**判定 77 个意图全判为缺口，P **0.1948** / R **1.0** / F1 **0.3261**（**正向**判定则是 0 / 77、F1 **0**） | `standardize/results_xfer_banking77_en.csv` 第 2–3 行；`results_xfer_banking77_zh.csv` 第 2–3 行数值相同 |

| banking77 真缺口意图共 **15** 个，故 77 个里精确率 15/77 = 0.1948 | `standardize/banking77_meta_en.json` 键 `n_gap_intents`；`banking77_meta_zh.json` 同键 |
| 同模型同语言内：5 个场景所需阈值 −0.6657 / −0.6633 / −0.6897 / −0.6792 / −0.6657，**极差 0.0264** | `standardize/results_auc.csv` 第 2 / 10 / 18 / 26 / 34 行「召回全部门槛的阈值」列；极差值见 `derived_metrics.csv` 键 `threshold.abs_5scenario_range` |

### 如果继续追问
- **「同一份 banking77，只是换模型，真的差这么多？」** → 是。同一语料，EN 模型 ABS 全量 AUC 0.9538，ZH 模型 0.7925（两份 `results_banking77_*.csv` 第 2 行「全量 / ABS」行）。覆盖度均值也不同：EN 0.8797、ZH 0.8386（两份 `banking77_meta_*.json` 键 `cover.mean`）。
- **「那你为什么不干脆每种模型重新标定阈值？」** → 可以，而且这正是我给的适用边界：同模型同语言内换语料/换规模是推荐的（极差 0.0264）；换模型或换语言必须重新标定。这条结论本身就是产物。
- **「领域内标准化不是号称更鲁棒吗？」** → 在合成语料上它是最好的（S3 alpha AUC 1.0），但那不等于鲁棒；它在真实语料上崩得最狠（0.4344 / 0.4946，低于随机水平附近）。合成语料的域是按主题构造的，这一解释是我的推断，不是产物里的结论。

### 不能说错的地方
- **不要说成「跨语料失效」。** 实测结论精确得多：失效发生在**跨模型 × 跨语言**；同模型同语言内**阈值刻度**极差仅 0.0264——但刻度稳不等于效果一样，换语料/换规模后召回仍需重新核对（KB 减半实测：沿用全量阈值精确率仍 1.0000，召回却掉到 0.4130，F1 从目标场景自身的 0.9474 掉到 0.5846）。
- 77 是**被判为缺口的意图总数**（其中 15 个是真缺口），要说清这是**反向判定**（`cover ≥ 0.6463 → 缺口`）的结果：R=1.0 全召回但 P 只有 0.1948。正向判定（`cover ≤ 0.6463 → 缺口`）是**检出 0 / 77、F1 = 0**，两个方向都不可用。不要把 77 说成「77 个缺口意图」。
- `_en` 与 `_zh` 两份 `results_xfer_banking77_*.csv` 的**前两行数值完全相同**（正向 0 / 77、F1 0；反向 77、0.1948 / 1.0 / 0.3261），差别只在末列基准（0.8148 vs 0.6207）；两份文件的「目标」列分别写 `banking77（bge-small-en-v1.5）` 与 `banking77（bge-small-zh-v1.5）`——**语料是同一份 banking77 英文文本，变的是嵌入模型**。不要声称这两行分别独立代表 EN 与 ZH 两次迁移。

## Q2「你说的形式化命题，不就是单调变换不改 AUC 吗？这也算贡献？」

### 问题原话
「你引的这个命题——严格单调变换不改变 AUC——这是已知结论吧？也能算你的贡献？」

### 一句话回答
**这条命题不是我提的，它是已知事实，我也没打算把它当贡献。** 我的用法是把它当**排除工具**：用 3 行判定把「凡是排序等价于绝对阈值的打分方案，在数学上不可能改进 AUC」这一整类说法直接证伪，从而省掉这一整类实验——实测 8 种打分里 ρ = −1.000000 的那 3 种，α 场景 AUC 全部恒等于 0.968，实验证实了这一点。

### 支撑数据
| 数据 | 出处 |
|---|---|
| 命题陈述：任何对 cover 施加的严格单调递增变换 g，都满足 AUC(g(cover)) ≡ AUC(cover) | `standardize/STANDARDIZE_RESULT.md` 第 41 行 |
| 3 行判定：ABS / S1 / S2 的 ρ 均为 **−1.000000**，α_AUC 均为 **0.968** | `standardize/mechanism.csv` 第 2–4 行（`spearman_与cover`、`alpha_AUC`、`是否单调等价` 三列，`是否单调等价`=True）；同判定见 `standardize/run_std.log` 第 165–167 行 |
| 反面同样有实测：非单调的方法确实能改变排序，S3 ρ=**−0.893715** → AUC **1.0**；S4 ρ=−0.972351 → **0.984**；S4b ρ=−0.814022 → **0.752** | `standardize/mechanism.csv` 第 5、6、9 行 |
| S6 去极值z 的 ρ 高达 **−0.999817**，但判为非单调，AUC 仍是 **0.968** —— 说明「ρ 接近 ±1」不等于「单调等价」，必须看判定列 | `standardize/mechanism.csv` 第 8 行 |
| 由此被排除的方案族已跑完消融：14 个变体（α 场景 AUC/F1/最优阈值） | `standardize/ablation.csv` 第 2–15 行；第 16–46 行为同一批变体在 5 个场景上的展开 |
| 非单调 ≠ 更好：S4b 双参考系(意图) α AUC 只有 0.752、F1 只有 0.4762 | `standardize/ablation.csv` 第 9 行 |

### 如果继续追问
- **「那你的贡献到底是哪两条？」** → 只有两条：段落级语义覆盖（替代整篇级打分）与三模块知识治理系统。标准化/迁移这条线是**探索性分析与负结果**，已从题目中剔除。
- **「你怎么证明 ρ=−1 就是排序完全一致？」** → Spearman ρ = ±1 与严格单调等价等价，这是定义层面的事实；我这边给的是 8 种打分逐一实测的 ρ 表（`mechanism.csv`），三行 ρ = −1 的方法 α_AUC 实测确实都等于 0.968。命题本身的 3 行证明写在 `STANDARDIZE_RESULT.md` 第 594 行的证明提纲处。

### 不能说错的地方
- **绝对不能说这是我提出的定理或新贡献。** 它的价值是排除工具，答不上来「它值不值当贡献」时直接认。
- 不要说「ρ = −1 所以 AUC 一定一样」就完事——要强调必须区分 ρ 接近 ±1 与真正单调等价（S6 的 ρ = −0.999817 实测 AUC 仍是 0.968，但它在 `是否单调等价` 列被判为 False），判定以 `是否单调等价` 列为准。
- 不要引用旧数值 0.936：本卡的基准一律用 `granularity.csv` 的 0.888（意图级）/ 0.8307（工单级）。

## Q3「你有什么负结果？」

### 问题原话
「除了做成的部分，你试过什么失败的东西？」

### 一句话回答
最典型的负结果是：**「跨场景阈值极差」这个度量本身可以被优化成假象**——某个方案把极差压到 0.0018（比基线 0.0264 小一个数量级），只看可迁移性它是最优的，但它的 AUC 只有 0.112，比随机还差。**「可迁移」不等于「有效」。**

### 支撑数据
| 数据 | 出处 |
|---|---|
| 方向对照实验共 **28 行 = 4 个场景 × 7 个打分方向** | `standardize/results_directions.csv` 第 2–29 行 |
| A2 `(max-top5)/max`：α 场景 AUC 仅 **0.112**、F1 **0.2941** | `standardize/results_directions.csv` 第 4 行 |
| A2 在 4 个场景上的「召回全部阈值」分别是 0.0001 / 0.0 / 0.0 / **0.0018** → 极差 **0.0018** | `results_directions.csv` 第 4、11、18、25 行；极差值见 `derived_metrics.csv` 键 `directionA2.4scenario_threshold_range` |
| 对照基线 ABS 跨 5 场景阈值极差 **0.0264** | `derived_metrics.csv` 键 `threshold.abs_5scenario_range` |
| A1、A3 在 α 场景同样只有 **0.096** | `results_directions.csv` 第 3、5 行 |
| A 系列里最好的 A4 `stop5-max` 也没赢：0.92 / 0.8509 / 0.8644 / 0.7981，逐场景对比基线 0.968 / 0.8075 / 0.9022 / 0.9135，**没有一个场景赢** | `results_directions.csv` 第 6/13/20/27 行 vs 第 2/9/16/23 行 |
| 方向 B（双向中心化）同样全面落后 | `results_directions.csv` 第 7/14/21/28 行 |

### 如果继续追问
- **「那这个度量还有意义吗？」** → 有，但不能单独用。它作为「同一方案在不同场景下稳定吗」的辅助描述仍然成立；问题在于它可以被方案本身反向优化。所以论文里我没有把它当结论指标，只当诊断量。
- **「固定检出比例那条路呢？」** → 也做了，同样是负结果：固定 25% 检出比例时 4 场景平均 F1 只有 **0.5522**（`derived_metrics.csv` 键 `directionC.fixed25_mean_f1_4scenario`），SD 0.0873 虽比 ABS 的 0.1452 小，但平均 F1 从 0.8289 掉到 0.5522（`directionC.mean_f1_sacrifice_ratio_fixed25` = 0.3338）。逐场景数据在 `standardize/results_directionC.csv`。

### 不能说错的地方
- 0.0018 是 A2 的**阈值极差**（越大越稳），0.112 是它的 **AUC**——两个是不同量纲，不要混说成「A2 性能 0.0018」。
- 极差对比要注明场景数不同：A2 是 **4 个**场景（alpha/beta/gamma/gamma-X），基线 ABS 的 0.0264 是 **5 个**场景（含 delta），两者来自 `derived_metrics.csv` 中两个不同的键。
- 不要说「所有方向都失败」——A4 `stop5-max` 在 α 场景确实比基线以外的其它变体高，只是没超过基线 ABS。

## Q4「你的 AUC 提升是算法改进，还是工程调参？」

### 问题原话
「你把 AUC 从 0.83 提到 0.96，这是算法上的改动，还是调参调出来的？」

### 一句话回答
是算法层面的改动：改的是**打分所依据的粒度**（整篇级 → 段落级），比较的是不同打分方案而不是超参，所以调参调不出这个差异。但我必须主动交代一个反向点：**最优统计变换随粒度反转，段落级不是唯一有效方向。**

### 支撑数据
| 数据 | 出处 |
|---|---|
| 段落级基准：工单级 AUC **0.8659**、意图级 AUC **0.968** | `granularity.csv` 第 7 行 `passage_level,max-cosine` 的 `auc` / `auc_intent_median` 列 |
| 整篇级基准：工单级 AUC **0.8307**、意图级 AUC **0.888** | `granularity.csv` 第 2 行 `doc_level,max-cosine` |
| 提升幅度：意图级 **+0.0800**（相对 +9.009%）、工单级 **+0.0352** | `derived_metrics.csv` 键 `granularity.intent_auc_passage_minus_doc`、`granularity.intent_auc_relative_gain`、`granularity.ticket_auc_passage_minus_doc` |
| **反向点**：整篇级 `max-min`（极差）意图级 AUC **0.928**，**高于**同粒度基准 0.888；但工单级掉到 **0.7829**（低于 0.8307） | `granularity.csv` 第 6 行 `doc_level,max-min` |
| 段落级 `max-min` 意图级 **0.88**、工单级 **0.78**，都低于同粒度基准 | `granularity.csv` 第 11 行 |
| 其余统计变换在两种粒度上全部低于同粒度基准（0.756/0.5239/0.7179 与 0.8088/0.6029/0.794） | `granularity.csv` 第 3–5、8–10 行 |
| 评测规模固定：工单 **2000** 条、标注 **371** 条，10 行全部同值 | `granularity.csv` `n_tickets` / `n_labeled` 列 |

### 如果继续追问
- **「那你的结论是『改粒度一定有效』吗？」** → 不是。数据不支持：段落级的 max-min 反而比基准低（0.88 vs 0.968），整篇级的 max-min 反而比基准高（0.928 vs 0.888）。能站住的结论是：**在实测范围内，段落级带来的 +0.0800 大于任何单一统计变换带来的变化，而最优变换随粒度反转、不稳定。**
- **「怎么保证不是过拟合你挑的这几个方案？」** → 10 行数据里的 5 个统计变换 × 2 个粒度全部列在 `granularity.csv` 里，不是挑出来的；而且 371 条标注在 10 行中完全一致。
- **「0.936 是多少？」** → 不要报这个数。当前口径下整篇级基准是意图级 0.888 / 工单级 0.8307，出处见上表。

### 不能说错的地方
- `granularity.csv` 有两个 AUC 列：`auc` = 工单级，`auc_intent_median` = 意图级。**0.968 和 0.888 都是意图级；0.8659 和 0.8307 才是工单级**。混用会被抓。
- **必须主动说出反向点**（整篇级 max-min 意图级 0.928 高于同粒度基准）。只报有利数字等于隐瞒，评委会自己算出反例。
- 不要把 +0.0800 说成「段落级是唯一有效方向」。

## Q5「腐化检测 F1 0.9466 是不是规则凑出来的？」

### 问题原话
「你这个 F1 0.9466，四条规则是不是硬凑出来的？」

### 一句话回答
做过完整消融，结论有三层：**四条规则必须联合**（去掉任意一条 F1 掉到 0.6809–0.6857）；**单独用任何一条都不行**（only_R2/R3/R4 的 F1 全为 0）；**R3 是冗余的**（去掉它 ΔF1 = 0）——这一条我主动说，因为它对我不利。

### 支撑数据
| 数据 | 出处 |
|---|---|
| 四条联合：P **0.8986** / R **1.0** / F1 **0.9466**，检出 69 篇 | `corrupt_rule_ablation.csv` 第 2 行 `all`；`metrics.json` 键 `corrupt.f1` / `corrupt.precision` / `corrupt.recall` / `corrupt.detected` |
| drop_R1 → F1 **0.6857**（ΔF1 **−0.2609**） | `corrupt_rule_ablation.csv` 第 3 行 |
| drop_R2 → F1 **0.6809**（ΔF1 **−0.2657**） | `corrupt_rule_ablation.csv` 第 4 行 |
| drop_R4 → F1 **0.6809**（ΔF1 **−0.2657**） | `corrupt_rule_ablation.csv` 第 6 行 |
| **drop_R3 → F1 仍是 0.9466，ΔF1 = 0.0**（平均风险从 1.08 降到 0.8667） | `corrupt_rule_ablation.csv` 第 5 行 |
| only_R1 单独用 F1 **0.6809** | `corrupt_rule_ablation.csv` 第 7 行 |
| **only_R2 / only_R3 / only_R4 单独用 F1 全为 0.0**（ΔF1 均 −0.9466） | `corrupt_rule_ablation.csv` 第 8–10 行 |
| 四条规则的权重 R1=3 / R2=2 / R3=2 / R4=1，判定门槛 score ≥ 3 | `metrics.json` 键 `corrupt.rule_weight`、`corrupt.score_threshold` |
| 各规则命中篇数：R1 32 / R2 38 / R3 32 / R4 88 | `metrics.json` 键 `corrupt.rule_hit_counts` |

### 如果继续追问
- **「R3 冗余为什么还留着？」** → 因为它在判定里权重为 2，命中 32 篇，去掉它对 F1 无影响但会降低可解释性（少一条规则，等于少一个能向业务方解释的信号）。这是取舍，不是缺陷。
- **「F1 这么高是不是因为标注太松？」** → ground truth 是构造注入的，62 篇注入、69 篇检出、7 个误报、0 个漏报（`metrics.json` 键 `corrupt.embedded` / `tp` / `fp` / `fn`）。
- **「那实际用起来召回 1.0 是不是过拟合阈值？」** → score_threshold = 3 是唯一的判定门槛，消融表里 9 个设置共享同一个门槛，差异全部来自规则组合。

### 不能说错的地方
- **不要只说「四条缺一不可」。** drop_R3 的 ΔF1 恰好是 0，说缺一不可会被这条数据当场推翻。正确说法是「四条联合最优，其中 R3 在判别上冗余」。
- only_R1 有 0.6809 的 F1，不是 0；只有 only_R2 / only_R3 / only_R4 是 0。
- 消融表里的 F1 列是**该设置自己的 F1**，`delta_f1` 才是相对 `all` 的变化量，两者别混。

## 翻数据的方法

### 一行自查
```bash
cd D:/26code/毕设/poc/kbgovernance && python check_numbers.py
```
这个脚本扫描三份文档里的每一个数值断言，逐个回到 JSON/CSV 产物核对分类，报告写到 `check_numbers_report.md`。**若报告里出现「指标类 UNSOURCED」计数不为 0，说明有数字在文档里但不在产物里——先别答辩，回去查。**

### 现场调出任一数字的两条路径
1. **直接翻产物**：CSV 用编辑器打开，表头是第 1 行，本卡所有行号按 1 起算；JSON 按键路径读。
2. **查派生量**：`derived_metrics.csv` 每行给 `derived_key` / `value` / `formula` / `inputs` / `source_files` 五列。凡是「算出来的」数字（极差、提升幅度、落后幅度）都在这里，能追到原始 CSV。
