# 非文献方向选题方案（中等偏上难度 · AI 占比可控 · 强落地）

> 调研日期：2026-10-12。配套第一份文档见《毕业设计选题调研.md》。
> 本文针对四条硬约束给方案：**① 难度中等偏上，7 个月内能真正做完；② AI 不占大头（用 GBDT/统计模型而非神经网络）；③ 能支撑约 70 页设计报告；④ 有大量开源可借鉴，不选冷门技术。**

---

## 0. 先说一个反直觉的判断：AI 占比低，反而是优势

老师的原话是「建议**融入**算法：深度学习算法、协同过滤算法、机器学习算法」——是"融入"，不是"以 AI 为主体"。这意味着：

| 把 AI 当主体 | 把 AI 当算法组件 |
|---|---|
| 需要 GPU 训练，受 8GB 显存限制 | GBDT / ARIMA 纯 CPU 跑，**零硬件风险** |
| 实验结果不稳定，答辩被追问"为什么涨了 3 个点" | 指标可复现，答辩问不出硬伤 |
| 撞车率高（人人都在做 RAG、YOLO） | 撞车率低，差异化在业务与决策层 |
| 老师怀疑"是不是套了个壳" | 明摆着是真做了算法工作 |

**结论**：把 70–80% 的工作量放在**数据工程 + 业务系统 + 决策逻辑**上，20–30% 放在**一个核心算法模块**上。这既满足"融入算法"，又避开所有落地风险。

**万一学院硬性要求"深度学习"**：加一个轻量 LSTM 或 1D-CNN 做**对照实验**即可——不是为了效果，而是论文里"传统模型 vs 深度模型"的对比章节能白送 5–8 页内容，且训练一个小时就能跑完。

## 2. 方案 A：基于图特征与可解释模型的交易欺诈检测与风险评分系统的设计与实现

> **推荐指数：★★★★★** —— 答辩素材最足，数据集最标准，开源实现最多

### 2.1 数据（公开、可直接下载、无版权风险）

**IEEE-CIS Fraud Detection**（Kaggle 官方竞赛数据）：

- 训练集 **590,540 条交易 × 460 列**，欺诈占比仅 **3.5%**（典型的极度类别不平衡）
- 文件结构 `train_transaction.csv` + `train_identity.csv`，两张表通过 `TransactionID` 关联 —— **天然的一张一对多关联表，ER 图有真实内容可画**
- `TransactionDT`、`TransactionAmt`、`ProductCD`、`card1~card6`、`M1~M9`、`C1~C14`、`D1~D15` 等匿名化字段
- 官方目标列 `isFraud`

来源：[Kaggle 竞赛页](https://www.kaggle.com/competitions/ieee-fraud-detection/data)

### 2.2 算法部分（纯 CPU，纯机器学习，占比约 30%）

```
① 特征工程
   · 类别特征：LabelEncoder / 目标编码（Target Encoding，需防泄漏）
   · 时间特征：TransactionDT 拆解为 时/日/周/月 + 距开卡天数
   · 聚合特征：按 card1 / card2 / device_id 分组，统计
     金额的 count / mean / std / max-min 等（v1→v2→v3 逐层聚合）
② 模型：XGBoost / LightGBM 梯度提升树
   · 对比基线：逻辑回归、随机森林、朴素贝叶斯
③ 不平衡处理：SMOTE 过采样 / 类权重调整 / 阈值调优
④ 图特征（差异化核心）：构建 card—device—IP 三元关系图，
   用 NetworkX 计算节点度数、连通分量规模、共享设备数
⑤ 可解释性：SHAP TreeSHAP 输出全局特征重要性 + 单笔交易的瀑布图
   （官方仓库 25.9k stars，是金融风控领域的事实标准）
⑥ 阈值策略：按业务容忍度调整判定阈值，输出分级风险（低/中/高）
```

依据：[SHAP 官方 README](https://github.com/shap/shap)、[LightGBM 官方参数文档](https://lightgbm.readthedocs.io/en/latest/Parameters.html)

### 2.3 系统模块（工作量在这里，占 70%）

1. **数据接入与清洗模块**：CSV 分片读取（590k×460 直接读会爆内存，必须分块）、缺失值处理策略配置、异常值检测
2. **特征工程流水线**：可配置的特征生成器，支持增量计算与结果缓存
3. **模型训练与评估模块**：超参搜索、交叉验证、混淆矩阵/ROC/PR 曲线/KS 统计量输出
4. **风险评分服务**：单笔交易实时打分、批量评分、风险等级判定
5. **可解释性分析模块**：SHAP 单笔归因、全局重要性、特征交互
6. **规则引擎**：可配置的高风险规则库（如"异地大额+新设备+夜间"），与模型结果**双引擎并行打分**
7. **规则-模型仲裁层**：冲突案例分析（这一层是论文的亮点章节）
8. **案件管理模块**：人工复核队列、复核结论回流、误报率统计
9. **可视化驾驶舱**：ECharts 实时看板、趋势图、分布对比图
10. **模型监控模块**：数据漂移检测（PSI 指标）、模型衰减监控、再训练触发

数据库设计（12+ 张表，正好满足 ER 图要求）：交易流水表、客户表、设备表、IP 黑名单表、特征表、模型版本表、预测结果表、规则配置表、案件表、复核记录表、审计日志表、用户与权限表。

### 2.4 为什么这个选题能过

| 老师的红线 | 本方案的回应 |
|---|---|
| 不能太简单 | 10 个系统模块 + 6 类算法工作，数据量 59 万×460 |
| 不能太难 | 全 CPU，无 GPU 依赖，无模型预训练，最大风险是内存管理（分块读取即可解决） |
| 融入算法 | XGBoost/LightGBM + SMOTE + 图特征 + SHAP，四类机器学习手段 |
| 不能是"基于 Python" | 题目里没有 Python，只有问题域 + 算法特征 |
| 查重 | 往届 14 个题目中 0 个涉及金融风控 |
| 70 页报告 | 模块多、图表多（PR/ROC/KS/SHAP 瀑布图/混淆矩阵）、实验多（5 个模型 × 3 种不平衡策略的对比矩阵） |

### 2.5 开源借鉴（不是冷门技术，全是大厂标准件）

- XGBoost / LightGBM 官方文档与示例
- SHAP（25.9k stars，金融风控解释性的行业标准）
- scikit-learn 完整 pipeline 文档
- 网络安全领域有大量 Fraud Detection 开源项目可对照 pipeline 写法
- 前端：ECharts / Ant Design（学校 Java 栈可接 Spring Boot）

### 2.6 风险与对策

| 风险 | 概率 | 对策 |
|---|---|---|
| CSV 加载爆内存 | 高 | pandas `chunksize` 分块；或先用 PostgreSQL/DuckDB 导入 |
| 目标编码造成数据泄漏 | 中 | 用 K 折目标编码，交叉验证内做 |
| 金融数据集"过于经典"导致撞车 | 中 | 差异化靠**图特征 + 规则引擎仲裁 + 漂移监控**这三块，而非预测精度 |

## 3. 方案 B：基于多序列时序预测与安全库存优化的门店补货决策系统的设计与实现

> **推荐指数：★★★★★** —— 撞车率最低，落地感最强，"从数据到决策"的闭环最完整

### 3.1 数据（公开、经典、有完整排行榜可对标）

**Rossmann Store Sales**（Kaggle 经典预测竞赛，11 年前的赛事，方案至今公开可查）：

- **1,115 家门店 × 2 年（2015-01-01 至 2015-12-31）逐日销量**，官方评测指标 RMSPE
- 三张表：`store.csv`（门店属性：类型、距离、营业时间、促销配合）、`train.csv`（逐日销量）、`test.csv`（未来 41 天待预测）
- 关键难点天然存在：**大量门店在促销日闭店**（`Open=0` 但销量非零）、**德国各州公共假日不同**（需合并外部节假日表）、**门店类型差异大**
- 这是**多序列时序预测**（1115 条独立序列）的经典 benchmark

来源：[Kaggle 竞赛页](https://www.kaggle.com/competitions/rossmann-store-sales/data)

可替换数据集（同一技术栈，备份方案）：
- UCI Bike Sharing（17,379 条小时级记录，含天气与季节）：[UCI #275](https://archive.ics.uci.edu/dataset/275/bike+sharing+dataset)
- Olist 巴西电商（10 万订单 + 订单评价）：[Kaggle](https://www.kaggle.com/datasets/olistbr/brazilian-ecommerce)

### 3.2 算法部分（约 20%，这正是本方案的优势）

```
① 统计模型基线（用 statsforecast，官方 4.9k stars）
   · AutoARIMA / AutoETS / AutoTheta 自动参数搜索
   · 官方声明：比 pmdarima 快 20 倍、100 万条序列 30 分钟跑完
② 机器学习模型：LightGBM 回归
   · 特征：日期拆解（年/月/周/日/星期）、促销标记、门店类型、
     距最近假日天数、滞后特征 lag1/lag7/lag14/lag28、
     滚动统计 rolling_mean/std（这是销量预测的核心技巧）
③ 模型对比与自动选优：按门店分组做滚动时间窗交叉验证，自动选最优模型
④ 预测区间：给出 80%/95% 置信区间（MSTL 处理多季节性）
⑤ 安全库存优化（决策层，非 AI）
   · 基于预测分布 + 提前期计算再订货点与订货量
   · 服务水平与库存成本的帕累托权衡曲线
```

依据：[statsforecast 官方仓库](https://github.com/Nixtla/statsforecast)（支持 ARIMA/ETS/Theta/MSTL/Croston 等完整模型族，含异常检测与交叉验证教程）

### 3.3 系统模块（工作量主体）

1. **多源数据接入模块**：销售流水 + 门店档案 + 节假日表 + 促销日历，四源关联与对齐
2. **数据质量治理模块**：闭店日零销量处理、缺失日期补齐、异常值识别（3σ / IQR / STL 残差检验）
3. **特征工程模块**：时间特征、滞后特征、滚动窗口特征、编码特征
4. **模型训练与自动选优模块**：多模型批量训练、滚动窗验证、自动择优、模型版本管理
5. **预测服务模块**：单店预测、多店批量预测、指定日期区间预测、置信区间输出
6. **安全库存与补货决策模块**：服务水平设定 → 再订货点计算 → 建议订货量 → 缺货风险与持有成本估算
7. **补货计划看板**：日历视图、缺货预警、临期商品提示
8. **效果回溯模块**：预测值 vs 实际值对比、误差归因、模型迭代
9. **可视化分析模块**：销售趋势与季节性分解图、门店对比、误差分布、帕累托曲线
10. **系统管理模块**：用户、角色、门店档案、促销计划维护

数据库设计（12 张表）：门店表、促销日历表、节假日表、销量流水表、商品品类表、特征表、模型版本表、预测结果表、库存配置表、补货建议表、补货执行记录表、系统用户表。

### 3.4 为什么这个方案可能是最优解

| 维度 | 说明 |
|---|---|
| **难度可控** | 没有任何需要训练的大模型，最难的部分是时间序列特征工程，而这恰恰是本选题要讲的内容 |
| **撞车率低** | 往届 14 题中，销量预测 **0 命中**；商城推荐（3 题）、点餐（1 题）都是推荐问题不是预测问题 |
| **70 页有内容** | STC 分解图、多模型对比表、误差分布、帕累托曲线、服务水平权衡图 —— 图表天然多 |
| **落地价值最强** | "预测 → 补货决策 → 执行 → 效果回溯"是完整闭环，答辩时演示效果最直观 |
| **算法够用** | ARIMA/ETS 是正统统计学习算法，LightGBM 是正统机器学习算法，双基线对比本身就是论文亮点 |
| **开源极多** | statsforecast 4.9k stars、LightGBM 27k+ stars、Kaggle 上数千份 Rossmann 方案可对照 |

### 3.5 风险与对策

| 风险 | 概率 | 对策 |
|---|---|---|
| 促销/闭店数据处理不当导致误差大 | 高 | 这正是论文要讲的重点，提前做 EDA 定位闭店日规律 |
| 1115 个序列训练慢 | 中 | statsforecast 官方称百万序列 30 分钟；可先只做 Top 50 门店再扩展 |
| 决策模块（安全库存）被认为"不是算法" | 中 | 论文中明确写成"预测驱动的库存优化"，用帕累托曲线证明服务水平与成本的关系 |
| 有人做过类似的销量预测毕设 | 中 | 差异化放在**安全库存决策 + 效果回溯闭环**上，而非预测精度 |

## 4. 方案 C：共享出行需求预测与运力调度优化系统（备选）

**数据**：UCI Bike Sharing（17,379 条小时级租车记录 + 天气 + 季节），或 NYC Taxi 行程数据。

**算法**：LightGBM / LSTM 双模型预测小时需求量 → 派整数理规划模型（目标函数含车辆周转成本与缺口惩罚）。

**系统**：站点车辆管理、调度指令下发、实时供需热力图、预测-调度效果回溯。

**特点**：调度优化这个决策层很有说服力（运筹学味道，评委喜欢）。**风险**：需求预测本身是热门题目，需要靠"调度优化"来差异化。

## 5. 方案 D：基于多源传感数据的工业设备故障预测与维护策略系统（备选）

**数据**：
- UCI AI4I 2020 Predictive Maintenance（1 万条，8 个特征，含机器故障标签）——但**样本量偏小、过于干净**，需要扩充
- 更推荐：NASA C-MAPSS 涡扇发动机退化数据集（多工况、多故障模式、序列型退化数据）——[NASA PCoE 数据集](https://www.nasa.gov/content/prognostics-center-of-excellence-data-set-repository)

**算法**：LightGBM 分类（是否将故障）+ LSTM / 1D-CNN 处理退化序列 + RUL（剩余使用寿命）回归。

**系统**：设备台账、传感器数据接入、健康状态评分、故障预警工单、维护策略建议、备件管理。

**特点**：工业场景有说服力，NASA 数据集是正规公开数据集。**风险**：RUL 预测有一定难度，需控制目标（只做"健康状态分级 + 何时该维护"而不做精确 RUL 回归）。

## 6. 方案 E：区域碳排放预测与情景分析可视化系统（最低撞车率，备选）

**数据**：Our World in Data 的 CO₂ 数据集（覆盖 200+ 国家，1960–2022 年，含人均 GDP、人口、分行业排放）。

**算法**：面板数据回归 / LightGBM 面板模型 + ARIMA 混合预测 → 情景分析（设定不同发展路径下的排放预测）。

**系统**：国别排放看板、多维对比分析、情景模拟器、预测报告生成、地图可视化。

**特点**：题材新颖、图表极其丰富（地图、时间轴、多轴对比），撞车率几乎为零，且完全避开往届所有领域。**风险**：题目里的"AI"成分最淡，如果学院卡"必须深度学习"，需要额外加内容；数据更新频率需要注意。

## 7. 70 页报告怎么凑出来（按方案 A/B 通用结构）

这是很多同学的真实痛点——系统做完了，报告写不满 70 页。核心认知：**页数来自图、表、实验，不是来自文字**。

| 章节 | 页数 | 内容构成 |
|---|---|---|
| 封面 / 声明 / 摘要（中英） | 6 | 摘要 500 字 + 关键词 |
| 目录 / 图表清单 | 4 | 目录 + 图目录 + 表目录 |
| 第1章 绪论 | 6 | 背景（3 页，可引行业报告数据）、国内外现状（2 页，引 40+ 篇文献）、本文工作与章节安排 |
| 第2章 相关理论与技术 | 9 | 数据集介绍 2 页 + 评估指标定义 2 页 + 涉及算法原理 4 页 + 技术选型对比表 1 页 |
| 第3章 需求分析 | 8 | 可行性分析 1 + 用例图 2 + 用例说明表 2 + 业务流程图/活动图 2 + 角色权限 1 |
| 第4章 系统概要设计 | 10 | **ER 图 2** + 数据库表结构设计 3 + 功能结构图 2 + 系统架构图 2 + 索引设计 1 |
| 第5章 系统详细设计 | 14 | 类图 2 + 核心模块时序图 4 + 流程图 3 + 关键算法伪代码 3 + 接口设计 2 |
| 第6章 系统实现 | 12 | **界面截图 8–12 张**（每张配 200 字说明）+ 关键代码片段 2 |
| 第7章 系统测试 | 8 | 测试环境 1 + **黑盒测试用例表 3**（20–30 条）+ 白盒覆盖率 1 + 性能测试 1 + 测试结论 2 |
| 第8章 关键实验与结果分析 | 12 | 实验设计 2 + **实验对比表 4** + **可视化图表 4** + 消融实验 1 + 结果讨论 1 |
| 第9章 总结与展望 | 3 | 结论 2 + 不足与展望 1 |
| 参考文献 | 3 | 40–50 篇（GB/T 7714 格式） |
| 致谢 / 附录 | 3 | 致谢 1 + 附录（核心代码、实验数据表）2 |
| **合计** | **≈ 98** | — |

即使实现部分精简到 8 页，也轻松超过 70 页。**关键动作**：第 8 章的实验对比表与消融实验要预留足够篇幅 —— 这既是页数来源，也是答辩时"你到底做了什么"的证据。

## 8. 最终建议

**首选方案 B（多门店销量预测与智能补货决策）**，理由排序：

1. **撞车率最低**：往届 14 题零命中，而同类结构（商城/点餐）都是推荐问题不是预测问题
2. **难度最可控**：全 CPU，无预训练，无显存风险，最大难点就是时间序列特征工程（而这正是要写的）
3. **落地闭环最完整**：预测 → 补货决策 → 执行 → 效果回溯，答辩演示时最有说服力
4. **开源最丰富**：statsforecast（4.9k★）、LightGBM、Kaggle 上数千份 Rossmann 方案，任一环节卡住都能找到参考
5. **AI 占比天然合适**：ARIMA/ETS + LightGBM 双基线，符合"融入机器学习算法"且不喧宾夺主
6. **图表素材最丰富**：季节性分解、误差分布、帕累托曲线，支撑 70 页毫无压力

**次选方案 A（交易欺诈检测与可解释风险评分）**，如果你的导师偏爱"有明确评估指标、听起来更硬"的方向，方案 A 同样优秀，且 SHAP 可解释性是天然的答辩亮点（"为什么判这笔交易是欺诈"能给出逐特征归因）。

**通用落地纪律**（避免延毕的四条）：

1. **第 2 个月末必须能跑通"数据 → 模型 → 一个指标数字"**。跑不出来立刻换数据集，不要硬扛。
2. **系统模块按优先级砍**：核心链路（第 1–6 模块）必须做完，管理后台与高级监控可砍。这是延毕保险。
3. **论文与系统并行写**，不要等系统做完再写。每完成一个模块立刻写对应章节。
4. **每周向导师汇报一次**，用"已完成模块 + 下周计划"的格式。后期改方向的代价远大于早汇报。

**下一步三件事**：

1. 从方案 B 或 A 里选一个，**本周内**下载数据集，跑一次基线模型（Rossmann 用 AutoARIMA + LightGBM 跑 RMSPE；IEEE-CIS 用 LightGBM 跑 AUC），确认能出数字。
2. 到教务处确认本校论文模板、查重率与 AIGC 率的具体阈值。
3. 拿最小可行结果去见导师，带着"我打算做这个方向，这是第一版结果"去谈——比空手谈选题通过率高得多。
