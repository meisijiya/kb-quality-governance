### 2.8 原型交互整改（2026-10-24 新增，来自三份 ego-browser 独立评审）

评审方法：三名子代理各自用 ego-browser 独立走查原型（互不参考），分别按交互规范、操作效率、可用性与对比度三个视角出报告，共 20 + 24 + 48 项发现。评审报告是临时记录，任务结束前删除；结论固化在本节 H1 ~ H7，每条都带可复核的具体问题与验收信号。

#### H1 上传控件无响应 —— 必须先修

- **事项**：两个上传区点击与键盘操作均无反应，无法完成「导入文件」这一主路径的第一步。
- **依据**：交互规范 A1（阻塞）；操作效率 #1（阻断）。实测：DOM 内 `input[type=file]` 数量为 0，点击未触发文件选择器，`Enter` / `Space` 无反馈，页面文本长度不变；元素却带 `role="button"` / `tabindex="0"` / `aria-label` / `cursor:pointer`，而 `app.js` 全文没有对应的 `click` / `keydown` / `drag` 处理器。
- **验收信号**：鼠标点击、`Enter`、`Space` 三种方式都能触发文件选择；选中文件后界面给出文件名与行数反馈；页面文本长度随之变化。
- **负责人**：维护者（W3）。
- **限定**：原型阶段只验证交互链路（选中 → 反馈 → 状态推进），不做真实上传；真实上传属 W7 的 C8 字段口径与 C11 起动命令。

#### H2 主路径入口被折叠与长列表双重埋没 —— 必须先修

- **事项**：从「语料已就绪」到「看到扫描结果」的两步跳转，入口都在两屏之外，且窄屏下侧栏折叠成无标签图标。
- **依据**：操作效率 #2（阻断）、#9（高）、#18（中）；可用性 M4。实测：上传页主 CTA 在 `y=2036`、页面 `scrollHeight=2118`（1248×949 视口下需滚动 2.28 屏才可见），被常驻展开的「文档列头对照表」占掉 441px；扫描页 CTA 在 `y=2006`；三个下载按钮分别在 `y=1258/1335`，也在首屏外；1024–1439px 区间侧栏折叠为 68px 宽，3 个导航按钮 `innerText` 为空且无 `title` / `aria-label`，可访问名丢失。
- **验收信号**：1248×949 与 1440×900 两个视口下，主 CTA 与下载入口均在首屏可见；1024–1439px 下三个导航按钮都有可访问名。
- **负责人**：维护者（W3）。

#### H3 状态与数据不一致 —— 必须先修

- **验收信号**：任一时刻页面上的徽标数、指标数、清单行数三者互相自洽；无命中时指标位显示灰破折号而非旧值；加载态有文字且 `aria-busy`；错误态提供不破坏数据的恢复入口。
- **负责人**：维护者（W3–W4）。
- **限定**：徽标与指标只在「本轮扫描已完成且有真值」时显示真数；其余状态按 design-taste-frontend 的「数据状态诚实」规则（0 打印 0，缺失打印灰破折号）。

#### H4 键盘与无障碍 —— 必须先修

#### H6 数据呈现与信任度 —— 必须先修

- **事项**：第三份评审（数据呈现与信任度视角）26 条发现（阻塞 2 / 高 9 / 中 12 / 低 3）里的六条硬伤：下载通道泄露真值列、缺口 P/R/F1 的统计单元从未声明、溯源指针指向不存在的目录、关键数字缺列级溯源、反向点缺席、耗时口径不实。
- **依据**：数据呈现与信任度视角的 ego-browser 独立评审（方法：ego-browser task space `kgq-data-review`，只读核对 `poc/kbgovernance/` 产物与 `detect.py` 源码；报告为临时记录，结论固化在本条）。
- **具体问题**：
  1. **下载泄露真值列**（阻塞）：界面承诺「下载的是源 CSV 原文，不做二次加工」（`index.html:767-776`、`app.js:613-622`），而这四个源文件表头本身含 `is_true_gap`（`top15_gaps.csv`）、`is_true_group`（`dup_groups_best.csv`）、`in_control_sample` / `is_dup_copy` / `dup_source` / `fp_reason`（`corrupt_docs.csv`）。界面刻意藏起来的真值会随一次下载落到用户硬盘，页面零提示。**这条同时是契约缺陷**——`GET /api/downloads/{name}` 返回原始 CSV 即等于对外提供评测答案，见 §2.3 C7 的补充口径。
  2. **统计单元未声明**（阻塞）：缺口 P/R/F1 的分母是去重后的 5 个业务意图（`detect.py:117-125`），却与簇级「命中数 7」并排成一行；读者按簇级复算会得 6/7=0.8571，与页面 0.800 对不上。
  3. **溯源指针失效**（高）：页面写「本页所有数字均取自 `data/` 下的真实产物」，但仓库根与 `system/prototype/` 下均无 `data/` 目录，真实路径是 `poc/kbgovernance/`。
  4. **关键数字缺列级溯源**（高）：只有三张口径表带「产物键」列；总览表的 P/R/F1 与命中数、命中规模表、腐化评测统计表（15 个数）、清单页 15 个指标格全无出处标记（实测扫描页 `<code>` 唯一键仅 16 个）。
  5. **反向点缺席**（高）：阈值 0.62 在 `gap_threshold.csv` 里是孤立尖峰（0.60→F1 0.5714、0.64→0.6667、0.66→0.4762），界面零敏感性呈现；漏报的真意图「数据导出权限申请」（cover 0.6342）与混进的误报簇「终端病毒处置」（0.6179）也未披露，与 ADR-0002 第 4 条冲突。
  6. **耗时口径不实**（高）：「三模块检测段合计 3.09 秒 / 仅覆盖检测段」不成立——`detect.py` 第 209 行 的 `t_all` 在 `main()` 首行，实为读 CSV + 聚类 + 三检测全程（只不含向量化），且页面分项无法复算出 3.09；「重复冗余检测 0.0 秒」只包住阈值分组循环（`detect.py` 第 373–375 行），不含 300×300 余弦矩阵（`detect.py` 第 361–364 行 只 print 不落盘）。
- **验收信号**：
  - **下载口径已定（2026-10-24）**：**保留全量列 + 下载区明示**「下载的是含评测标注列的原始产物，仅用于论文溯源与复现」，不裁剪视图。理由：`docs/技术方案/本科版实施方案.md` §2「M-系统·Web 交付」要求「直接下载 poc/kbgovernance/ 已产出的 CSV」，Issue #3 断言清单第 10 条要求「下载的 CSV 与源文件逐字节一致」——裁剪会同时违反这两条，并让「逐字节一致」这条可机读验收信号失效。对应义务：下载区必须明示，**不得静默下载**；清单页面本身仍不展示任何真值列。已落 `system/openapi.yaml` 的 `GET /api/downloads/{name}` 描述与 `system/README.md` 已知歧义第 11 条。
  - 缺口页写成「7 缺口簇 / 5 个业务意图」，P/R/F1 加「（意图级）」后缀；三类清单的 count 单位统一显式标注（簇 / 篇 / 组）。
  - 所有溯源指针改成仓库真实相对路径 `poc/kbgovernance/…`。
  - 每个指标格都能指到「文件 + 列」；扫描页 `<code>` 唯一键从 16 个补到覆盖全部主指标。
  - 缺口页补阈值敏感性（0.60 / 0.62 / 0.64 / 0.66 四档 F1）与反向点披露。
  - 耗时只写「本次实测（跨机器波动）」，口径按 `detect.py` 实际计时范围表述，不复算不出分项。
- **负责人**：维护者（W3）。
- **通过项（同轮核对成立，不必重复查）**：真值列在 DOM 全量扫描 0 泄漏；F1=1.0000 乐观值提醒 4 处都在；三类统计单元不可横比的提示在位；无评测基线显示「—」且明写不补数；缺失耗时用「—」+「未落盘」而非填 0；需求阈值 60 秒 / 2 秒已标「非实测」；覆盖度百分比与原始值并列并有刻度线标阈值；风险分与规则组合一一对应且不以颜色为唯一编码；主文档选举只给定性表述；腐化 Tab 主动交代「共 69 / 已加载 12 / 代表行」；重复清单 22 行与产物逐行一致且下载 = 展示。
