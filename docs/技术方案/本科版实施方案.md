### 0.2 为什么开发窗口只有 10 周，且论文必须并行

三条理由，按重要性排序：

1. **单机单线程，串行会把风险全堆在末尾。** 本课题的算力是 bge-small-zh-v1.5 纯 CPU 推理，没有 GPU 也没有多机，所有实验耗时由一台机器串行承担（当前有效实测：向量化 14.61 秒、三模块检测合计 3.09 秒，均来自 `metrics.json`）。这意味着开发期一旦拖期，**没有任何富余算力去并行补跑**。若采用「先做完系统再开始写论文」的串行排法，论文的 6 章全部压在最后 4 周，任何一次导师改稿或查重超标都会把全文顶到答辩周，而答辩周不可压缩。
2. **时间随时可能缩水。** 用户给定的是 3–4 个月区间，本文件取上界 17 周。若实际可用时间只有 13 周，被砍掉的必须是**排在最后的写作阶段**，而不是被埋在中间的标注与实验。因此本排期把不可压缩的工作全部前置（标注在 W3、实验图表化在 W5–W6、开发在 W7–W9），留出 W10–W14 顺次倒推的写作链条，且链条上任一环节都能向下砍而不产生空洞。
3. **人工标注是唯一无法靠 vibecoding 加速的环节。** 代码、图表、页面都可以由 AI 快速生成，但双人独立标注必须等第二个人有空。这块时间**长度不可压缩、起点不可控**，因此被排到 W3 并标为关键路径（详见 §6 的关键路径段）。

### 0.3 三章的一致性约束

本文件的 §2（必做范围表）、§3（主动砍掉表）、§6（时间表）必须互相一致：**§6 里出现的每一项功能，都能在 §2 必做表里找到对应行；§2 里每一行的「若时间富余再补」条件，都指向 §3 已砍掉的具体项。** 任何一次范围增删，必须同时改这三章，只改其一会导致排期与范围脱节。

## 1. 题目定稿

### 1.1 定稿题目

**《基于语义聚类与时效性分析的企业知识库质量治理系统设计与实现》**

采用附录 A 的**变体 C**。

### 1.2 为什么不定稿变体 A（承诺「阈值可迁移性评测」）

变体 A 的题目是《基于段落级语义覆盖与阈值可迁移性评测的企业知识库质量治理系统设计与实现》。它比变体 C 多承诺了一件事：**阈值可迁移性评测**。

**不承诺它的理由只有一条：这条立论已经被自己的实测修正掉了，把修正掉的结论写进题目等于自己给自己埋雷。**

具体地说，写进题目就必须在答辩时回答「你的可迁移性评测协议是什么、跨语料表现如何」，而实测结论是：

| 事实 | 出处 |
|---|---|
| 绝对阈值锚定的是「模型 × 语言」的刻度；同模型同语言内跨场景阈值极差仅 0.0264，跨模型或跨语言则全线崩溃 | 极差 0.0264：`derived_metrics.csv` 的 `threshold.abs_5scenario_range`（输入取自 `standardize/results_auc.csv` 的五场景 ABS 阈值）；跨语言崩溃：`standardize/results_banking77_en.csv` |
| 中文语料上标定的 `cover ≤ 0.6463` 搬到 banking77（bge-small-en-v1.5）语料，**正向判定一个缺口都检不出来**（检出 0 / 77，P=0，R=0，F1 = 0，而该场景自身最优 F1 是 0.8148）；判定方向反过来则 77 个意图全被判成缺口（F1 0.3261）——两个方向都不可用 | `standardize/results_xfer_banking77_en.csv` |
| 「可迁移性」这个指标本身可以被优化成假象：有方案跨场景阈值极差只有 0.0018，但 AUC 是 0.1120，比随机还差 | `standardize/results_directions.csv` |

也就是说，**「可迁移性」在本课题上不是一项可交付的方法，而是一个需要靠一整章篇幅去划定失效边界的负结果**。17 周窗口里，把这个负结果讲清楚所需的篇幅（形式化命题 + 评测协议 + 边界表 + 度量陷阱）会挤掉系统实现本身；而题目一旦承诺了它，砍掉就变成「没做到」。

变体 C 只押一件事：**段落级语义覆盖度**，加上三模块的完整系统实现。实测值（数据来源 `poc/kbgovernance/granularity.csv`，`doc_level/max-cosine` 与 `passage_level/max-cosine` 两行）：意图级分离度 AUC 0.968 对照整篇级 0.8880，工单级 0.8659 对照 0.8307。

这里必须把立论强度定准。段落级在两种聚合口径下都优于整篇级，但增量是**同一量级内的有限提升**（意图级 +0.080，工单级 +0.035），不是数量级差异；而且同一张 `granularity.csv` 里的 `doc_level/max-min` 意图级 AUC 是 0.928，反而高于 `doc_level/max-cosine` 的 0.8880（详见 §4 E2）。因此论文的表述档位只能是「**在同一嵌入模型与同一打分形式下，检索粒度是一个经验证有效的因素**」，不能写成「大幅提升」或「粒度越细一定越好」。这是全部实测支撑得住的部分。

### 1.3 定稿题目的立论落点（答辩第一句话）

> 本系统用语义聚类把无标签工单归并成业务意图，用段落级语义覆盖度判定哪些意图没有知识文档支撑，用时效性规则识别内容腐化，用余弦相似度识别重复冗余；三类缺陷合并为一份可执行的治理清单。算法改进点是把检索粒度从整篇文档下沉到段落：同一嵌入模型、同一 `max-cosine` 打分下，意图级分离度 AUC 由 0.8880 提升到 0.968，工单级由 0.8307 提升到 0.8659（`poc/kbgovernance/granularity.csv`）。
>
> 立论强度按实测限定：这是同一打分形式下的粒度效应，增量为有限幅度；本文同时如实报告 `doc_level/max-min` 意图级 AUC 0.928 高于 `doc_level/max-cosine` 的 0.8880（见 §4 E2），即「改粒度一定更好」过强，本文主张的是「在同一打分形式下改粒度有效」。

## 8. 答辩四个必答风险

> 三个内容风险（风险一 / 二 / 三）按 17 周排期校准过：**不存在「等查重前还有时间补实验」这类表述**。排期里 W10 是系统与实验的硬冻结点，W14 是查重点，W15–W16 是缓冲，W17 是答辩。任何一个实验结论在 W10 之前没有落进产物文件，它在答辩时就不存在——三个风险的话术因此全部只引用已落盘的数字，不留「回头再补」的余地。

### 风险一：自造数据被质疑「答案写进题里」

**质疑原话**：数据是你自己生成的，那缺陷位置也是你自己埋的，指标当然好看。这不能证明方法有效。

**应对（按顺序讲，不要跳步）**：

1. **先承认这个质疑是成立的**——在只有自造语料的情况下，指标无法排除「方法只是识别出了我埋设时的书写特征」。这是事实，不回避。
2. **再给出防作弊设计，并如实交代它的实测结果**：语料里按逐篇独立抽样额外埋入了「自然陈旧但不算缺陷」的对照文档（生成脚本取值带：600–900 天未更新但内容无误；**实际篇数以 W2 落盘的 `ground_truth.json` → `control_doc_ids` 为准，不用抽样率代替篇数**）。**这批文档的唯一作用就是给规则制造真实的边界模糊性——若不设此对照，腐化模块会取得虚假满分。** 实测腐化模块 P=0.8986、R=1.0、F1=0.9466（`metrics.json` → `corrupt`）：7 篇误报**全部只由 R2（更新时间超 18 个月）与 R4（同域存在更新文档）这两条日期驱动的规则触发**，其中 6 篇来自这批对照文档，第 7 篇是重复件继承了主文档的陈旧 `last_modified`。**这里主动交代一个已知局限**：规则引擎无法区分「真过期」与「只是很久没更新」，本文的腐化检测在这一维度上是有偏的。W2 落盘 `control_doc_ids` 后，对照集的逐篇判定结果即可核。
3. **再给出粒度消融**（`poc/kbgovernance/granularity.csv`）：同一 `max-cosine` 打分下，段落级 AUC 意图级 0.968 / 工单级 0.8659，整篇级 0.8880 / 0.8307；文档级再做统计变换（`max/std`、`max/top5mean`、`max-top5mean`）意图级只有 0.496 / 0.776 / 0.832，段落级同三种为 0.704 / 0.888 / 0.920。如果方法在识别埋设特征，改粒度与改打分都不会带来系统性提升。**并且主动交代反向点**：整篇级换成 `max-min` 时意图级反而到 0.928，高于本文基准的 0.8880。这说明本文观察到的是「在选定打分形式下粒度有效」，不是「粒度决定一切」。
4. **最后给出外部数据佐证**：banking77 上方法仍然有效（数据在 `standardize/results_banking77_en.csv`，已跑完不需重跑）——**这一条只用来证明「方法不只在我编的数据上有效」，不作为本文主张，因为题目不含跨语言主张**。
5. **主动划边界**：论文的定位是「在有 ground truth 的场景下量化评估知识治理方法」，不是「在真实生产数据上验证」。自造语料的优点恰恰是 ground truth 完全已知——真实客服数据里根本拿不到「哪些问题没有被覆盖」的标注。

**禁忌**：不要说「我的数据和真实数据很像」。不要说「差异可以忽略」。**不要说「误报只有 7 篇，说明模型在读内容证据而非只看日期」——这 7 篇误报恰恰全部只由日期驱动的 R2/R4 触发，与实测相反。也不要说「7 篇误报全部来自对照文档」——实际是 6 篇来自对照集，第 7 篇是重复件继承了主文档的陈旧 `last_modified`。**

### 风险二：0.95 阈值下 F1 = 1.0，是不是数据太简单

**质疑原话**：你重复检测 F1 是 1.0，一分不差。这显然是过拟合或者数据太简单。

**应对（必须先说 1.0 是乐观值，再给真实基线）**：

1. **主动定性**：`dup_threshold.csv` 中 0.95 阈值下组级与文档级 P/R/F1 均为 1.0，**这是乐观值，原因是埋设的重复件仅差 4 处同义词**，整篇级下重复组的组内最大余弦集中在 0.9545–0.9845（均值 0.9796，`granularity_dup.csv` 的 `doc_level` 行），阈值 0.95 恰好落在这一簇的下方，不存在误判空间。顺带如实报告：段落级下同一簇的区间是 0.5671–1.0000（均值 0.9803），下界远低于 0.95，**这也正是重复检测必须留在整篇级做、不能照搬段落级的原因**，与 §4 E2 的粒度结论互为佐证。

4. **给出工程建议**：论文明确写「生产环境建议取 0.90 附近并配合主文档人工确认」，把 1.0 的成因和 0.7037 的现实一起交出去。

**禁忌**：不要把 1.0 当作卖点往大了说。这条是送分题，主动降级比被追问降级好。

### 风险三：形式化命题是已知事实，只能写成形式化说明 + 实测佐证

**质疑原话**：你那个「严格单调变换不改变 AUC」的命题，是排序指标的基本性质，谁都知道。这算什么创新？

**应对**：

**应对（按顺序讲）**：

1. **先交代真实排期**：开发 W1–W10、论文全程并行写作、W15–W16 留了两周缓冲，W17 答辩。这 17 周里排掉的是范围，不是质量——被砍的每一项都在 §3 有理由，砍掉的是演示视频、压测、分页排序、报告排版这类**不产生结论**的东西。
2. **主动说明哪些是砍的、哪些是没打算做的**：演示视频（改为现场跑系统）、压测（单机单用户，压测结论必然是「无瓶颈」，与 `metrics.json` 的 `total_seconds=3.09` 是同一句话）、报告排版（改为直接下载已产出的 CSV）。**这三项砍掉不影响论文的任何一条结论。**
3. **交代 W8 的降级判断**：**若 W8 末系统骨架未通，降级为「CLI 工具 + 一页静态报告」，不再做 Web。** 理由要讲清楚——**在只有 3–4 个月的情况下，一个能跑的三层分报告页远胜于一个做不完的看板**。评审看的是「这个系统能不能跑出治理结论」，不是「有没有前端框架」。真降级了也要如实说，论文第 4 章的架构图相应改成 CLI + 报告页。
4. **把不可砍的四项点出来**：段落级覆盖（题目立论支点）、三模块检测（题目里「治理」二字的全部内容）、FastAPI + SQLite 轻量看板（老师红线不许空壳管理系统，降级只到 CLI + 静态报告，不到纯 CLI）、指标可复现（`metrics.json` + `run_all.log`，是前三个风险话术的共同底牌）。**这四项在时间压缩下全部保留，是范围取舍的判断依据。**
5. **用可复现性收尾**：现场跑 `run_all.sh`，当场展示 `metrics.json` 与 CSV 落盘。**这是对「时间紧所以做得糙」最有力的反驳**——产物是逐字节可复现的，不是手工凑出来的数字。

**禁忌**：不要把砍掉的功能说成「其实是做了只是没展示」。不要为赶时间而临时改 `metrics.json` 里的数字——数字一旦在答辩现场对不上，全部三个风险同时失效。
