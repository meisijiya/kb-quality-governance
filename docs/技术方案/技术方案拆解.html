第 5 章：唯一的算法改进点怎么算的

§5.1 · 整篇编码把多主题平均掉 → 切段落后取两级 max 聚合；§5.1.3 用一整组失败实验堵死「换个归一化就能提升」这条追问

cover(t, di) = maxp ∈ Pi cos( e(t), e(p) )
cover(t) = maxdi ∈ D cover(t, di)

先段落内取 max、再文档间取 max —— 两级 max 正是让「一篇文档只讲一个子主题」不再被平均掉的原因。段落连续排列使 np.maximum.reduceat 一次向量化完成聚合，无需 Python 循环，2000×1852 矩阵乘法秒级。

风险与主动放弃：四类风险 + 砍掉三件事

第 8 章 风险与对策 · 这一章是写作期元文档，不进论文正文，但内容要落进论文第 7 章与答辩话术

8.1 技术风险

HDBSCAN 参数敏感（mcs 5→10 时 F1 不变，风险可控）· 相似度计算规模（当前秒级，2000 篇仍可接受，尚未实测）· 阈值稳定性。

阈值风险已被重新定性：不是「跨语料失效」，而是「跨模型 × 语言失效」——同模型同语言内极差仅 0.0264。

8.1.1 立论方向风险

原计划的第二个改进点「语料基线标准化」整体不成立：域内标准化在同一份 banking77 语料上、换两个 embedding 模型（bge-small-en-v1.5 / bge-small-zh-v1.5）分别只有 0.4344 / 0.4946（等同随机），而基线绝对阈值为 0.9538 / 0.7925。

路线已在 D14 前关闭，题目定为变体 C。缓解方式：用「预测 → 证伪 → 修正」的完整叙事呈现，这在方法论上比「猜对了」更有说服力。

8.2 数据风险

本课题最大的单点风险：自造数据被质疑「答案写进了题里」。

对策：① 双轨验证（自造 + banking77）② 按逐篇独立抽样埋设「自然陈旧但不算缺陷」对照文档，量化规则无法区分「真过期」与「只是很久没更新」③ 公开生成脚本与种子 ④ 主动讨论自造数据局限。

8.3 工程风险

Web 系统开发挤占算法时间。完整系统约需 13 个工作日（计划估算，非实测：数据扩量 1.5 + 阈值论证 1.5 + Web 4 + 论文 5 + 答辩 1）。

真正的瓶颈是人工标注（预算 300 条）——这是唯一无法通过编码加速的环节，必须在开题阶段就与导师确认时间预算。

08

答辩：8 个必答问题，答案已经写好了

§7.4 高频追问 12 条 + 8b · 这里挑出最可能被问的 8 条，每条都标了「方案里有没有给出可用数字」

Q1数据是真的吗？为什么不用公开数据集？
公开数据集只有「客户问什么」，没有配套的「知识库文档」，无法构造「哪些问题被覆盖了、哪些没有」的 ground truth。因此 ground truth 必须自建——而自建数据最容易被质疑「是不是把答案写进了题里」。对策是双轨验证：自造语料证明功能，banking77 证明方法不依赖我的数据。这是本设计最重要的防质疑手段。
Q2算法改进点是什么？
一个：把检索粒度从整篇文档改为段落级，意图级分离度 AUC 从 0.8880 提升到 0.968。「提出更好的打分函数」这条路实测后走不通——严格单调变换不改变 AUC，因此分位数、z-score 这类「换刻度」方案在数学上不可能改进排序类指标。这条命题是排除工具，不是第二个改进点（详见 §5.3 定位说明）。
Q3为什么用 bge-small 不用更大的模型？
三个理由：权重下载量 95.8 MB、换机器可复现；任务只需域内相似度比较，不需要极限语义判别；大模型会把 CPU 推理速度拖慢一个量级，影响「全量扫描 ≤ 60 秒」的性能承诺。工程确定性在这里比精度更重要。
Q4为什么不用 KMeans？
工单是无标签数据，事先不知道有多少业务意图——实际分出的簇数远多于预设的意图数。KMeans 必须预先指定 K，且对离群点敏感，而工单数据天然含长尾噪声。
簇数 95 / 88 为无出处项 审计文档已判：受审产物只记录阈值扫参，无总簇数列，论文中不可引用该数。
Q5为什么不用大模型 / LLM 来判断？
成本与不确定性。判定逻辑是「聚类 + 相似度 + 规则」，全程可解释、可复现、毫秒级。若用 LLM 判断，300 篇文档的重复检测会产生数千次调用，成本高且每次输出不确定，无法给出稳定的 P/R/F1。
Q60.95 阈值下 F1 = 1.0，是不是数据太简单？
是，论文里明确写了这一点。埋入的重复件仅差 4 处同义词，组内余弦 0.9545–0.9845（整篇级口径），属于乐观值。真实语料的合理预期是 0.90 阈值下组级 F1 ≈ 0.7037，论文以这个数字作为基线。0.85 处组级 F1 仅 0.1778（过度合并），说明阈值曲线确实有区分度。
Q7腐化检测是规则匹配，会不会太简单 / 不通用？
规则本身简单，但规则工程是核心工作。R4 加两道约束（对方领先 ≥ 365 天、标题包含度 ≥ 0.50）后命中数从全量收敛到 88 篇，这个修正过程本身是论文素材。四规则贡献度消融：F1 = 0.9466 来自四条联合，任一单规则都到不了（only_R2 / only_R3 / only_R4 的 F1 恒为 0，only_R1 也只有 0.6809）；去掉 R1 / R2 / R4 分别掉 0.2609 / 0.2657 / 0.2657，而去掉 R3 一位不掉（ΔF1 = 0），说明 R3 在本语料上冗余，如实写进论文。
Q8阈值 0.62 是不是过拟合到我的数据了？
同一模型、同一语言内不是：5 个场景迁移实验所需阈值极差只有 0.0264。不过刻度稳不等于效果一样——banking77 全量 → KB 减半时，ground truth 从 15 个缺口意图变成 46 个，沿用全量阈值的 S1 / S2 精确率仍 1.0000、召回掉到 0.4130，F1 从目标场景自身的 0.9474 掉到 0.5846，所以这一档的答案是「阈值可复用，召回要重新核对」。跨模型或跨语言确实会崩：中文语料标定的 cover ≤ 0.6463 搬到 banking77 英文语料，正向判定一个缺口都检不出来（F1 = 0，该场景自身最优 F1 是 0.8148）；反向判定则 77 个意图全被误判为缺口（F1 0.3261）——两个方向都不可用。准确表述是：绝对阈值锚定的是「模型 × 语言」的刻度，模型和语言不变时它很稳，变了就崩。
8b你之前预测「领域内标准化最优」，实测证明是错的，这不是打脸吗？
是预测错了，不回避。但保留这个预测-证伪过程比一开始就说对更有价值：① 它暴露了一个隐蔽陷阱——合成语料里缺口分散在不同业务域，恰好符合分组标准化的假设，真实数据里缺口是整片缺失；② 证伪它让我发现了命题 5.1，把一大类「我们做了归一化所以更鲁棒」的说法一刀切掉，这是可验证的正向贡献；③ 还发现「可迁移性」这个指标本身可以被优化成假象（有方案阈值极差仅 0.0018，但 AUC 只有 0.1120，比随机还差）。结论：能诚实说清「什么方法在什么条件下有效、什么条件下无效」，比多凑一个看起来漂亮的方法更有研究价值。

Dxfer 判定式的符号缺陷：已修产物，修正后结论比原来更强 已修

复审在 standardize/exp4_banking77.py 里查到一个实打实的代码缺陷：第 160 行取 med_all = intent_auc(-cover, ...)，得到的是 −cover 的中位数（值域 [−1, 0]）；第 204 行却判 v <= 0.6463 —— 这个条件对该值域恒真，所以不论阈值取多少、cover 分布如何，都会「全部判为缺口」。

佐证：中英文两份 xfer 产物的 cover 分布不同（min 0.6014 vs 0.6547），却报出完全相同的 77 / 0.1948 / 1.0 / 0.3261——若是真实阈值效应，英文侧 min 已高于 0.6463，结果不可能与中文侧相同。按正确写法（v >= -0.6463）重算，英文场景 F1 应为 0，比记录的 0.3261 更差。

已按「修产物重跑」处置：判定式改为 v >= -0.6463（正向）与 v <= -0.6463（反向），en / zh 两组实验全部重跑，产物与全部引用点同步更新。同时删掉两份与 _en 内容相同的重复副本（results_banking77.csv / results_xfer_banking77.csv）——后者还携带已被推翻的旧判定结果，留着会与新产物矛盾。

修正后的真实结论更强：正向判定在英文与中文两个目标语料上一个缺口都检不出来（检出 0 / 77，P=0，R=0，F1 = 0；而该场景自身最优 F1 是 0.8148 / 0.6207）；反向判定才得到 77/77 全判为缺口（F1 0.3261）。缺陷方向恰好把结论讲反了一半——阈值不是不准，是根本不在目标语料的刻度上，正着过不去、反着全中。

复查时又挖出一个连带缺陷：xfer 表的「目标」列被写死成 banking77 英文，于是 results_xfer_banking77_zh.csv（中文模型跑的、末列基准 0.6207）自曝为英文语料，与同表数值自相矛盾。已改为随嵌入模型输出 banking77（bge-small-en-v1.5） / banking77（bge-small-zh-v1.5） 并重跑两组——指标值一个字节都没变，只有标签变准。这也钉死了一件事：banking77 的语料文本恒为英文，变的只有嵌入模型，所以「目标场景」必须标成「语料 + 模型」的组合。

EGPU 与向量数据库：以本地跑通为准，模型固定，部署是锦上添花 已定
