# ADR-0002：论文数字以 PoC 机读产物为唯一来源

- **状态**：已采纳
- **日期**：2026-10-19
- **相关**：[`poc/kbgovernance/README.md`](../../poc/kbgovernance/README.md)、[`docs/技术方案/数字溯源审计.md`](../技术方案/数字溯源审计.md)

## 背景

本课题的所有交付物（论文正文、答辩 PPT、系统页面、图表）都会反复引用同一批指标数字：三类缺陷的 P/R/F1、粒度消融的 AUC、腐化规则的 delta_f1、各模块耗时。选题调研阶段已经出现过一次典型事故：早期裁决文档里有 5 条判断被后续实测推翻（HDBSCAN 噪声、torch 环境坑、方案 7 的权重层设计、方案 10 的风险等级、方案 7 的卡点性质），且原裁决文档中的多个数字在实测产物里根本找不到出处。

另一个已确认的失败模式是「可迁移性」这类指标本身可以被优化成假象：有方案跨场景阈值极差仅 0.0018，但 AUC 只有 0.1120，比随机还差。

这说明：**数字本身不构成证据，数字的出处才构成证据。**

## 决策

1. **唯一来源**：`poc/kbgovernance/` 下的机读产物（`metrics.json` 与各 CSV）是本课题全部数值的唯一合法来源。文档、PPT、论文中出现的每个指标值，必须能在产物文件里按「文件路径 + 列/行」原样找到。
2. **禁止反推**：不得从 `RESULT.md`、方案文档正文、聊天记录等叙述性文本中抄取数字。`RESULT.md` 是 PoC 阶段的说明文档，不是数据源。
3. **数字纪律门禁**：`poc/kbgovernance/check_numbers.py` 扫描文档中的每个数值断言，判定其能否在产物中找到出处。找不到出处的格子一律写 `【无出处】`，不允许补一个看起来合理的数。
4. **反向点必须同表呈现**：与结论方向相反的实测数据不得只报其一。例如粒度消融中 `doc_level/max-min` 意图级 AUC 0.928 高于同粒度基准 0.8880，必须与正向结论并列。
5. **失败也要落盘**：消融、跨语料迁移等负结果同样写成机读产物（如 `corrupt_rule_ablation.csv` 中 `drop_R3` 的 `delta_f1=0`），并作为主动报告的负面发现写进论文，而不是省略。

## 后果

- **正面**：每个数字可被第三方在几分钟内独立复核；论文与代码不会出现口径漂移；选题阶段的翻车模式被制度性堵住。
- **代价**：写作速度变慢——任何数字在写进文档前都要先确认它已落盘。这是有意的取舍。
- **延伸**：`docs/技术方案/数字溯源审计.md` 是这套纪律的一次完整执行样本：逐条审计技术方案中的数值断言，标出一致 / 不一致 / `【无出处】` 三种判定。文档数字发生变更时，审计需重跑。
